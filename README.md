# Iroto Web — logo v3 browser / no fullscreen 1

版本：`2.14.1-beat-haptic-stronger-logo-v3-browser-nofs1`

基于此前确认的 **Iroto Web beat haptic stronger logo v3 browser** 修改；不是重新使用旧的无全屏试验版。

## 本次改动

关闭程序主动进入全屏的入口。Android 和 iPhone 均保持普通浏览器页面模式。开始演奏、停止后重播、替换照片及保存视频都不会主动申请全屏，也没有自动恢复全屏的定时器。

更新了资源查询版本和兼容性窗口的版本文字，以区分此次修改。

## 方向锁定

保留开始演奏时的 `screen.orientation.lock()` 尝试和原来的失败处理，保留每次演奏开始时记录的方向基准。非全屏下，浏览器可能拒绝系统方向锁定；此时演奏可以继续，但页面仍可能随手机的自动旋转而改变方向。

**内部传感器方向基准不变，不等于系统屏幕已被锁定。** 本版没有声称实现非全屏下的可靠系统旋转锁定，也不会为锁定屏幕重新进入全屏。

## 保持原样

- 传感器处理、准星平滑、播放时自动回正：未改。
- 加速度依旧不参与准星控制。
- 第一拍双脉冲、其余三拍短震的节拍震动：未改。
- 照片等比例显示、照片比例录制画布、视频保存：未改。
- 网页样式、SVG logo、三种 PNG 图标及 manifest：逐字节保持原样。manifest 仍为 `display: browser`。

## 检查范围

JavaScript 语法检查通过。对比基准文件，`app.js` 除版本常量、一处说明注释和全屏入口函数外没有修改。

在本地 Chromium 的离线页面测试环境中检查了竖屏、横屏，以及方向锁定被拒绝或不可用的情况：三语切换、选图显示、播放/停止/重播、点击显示/隐藏控制、替换照片、返回选择页均通过；另外测试了竖屏实际 MediaRecorder 录制及下载。所有场景的全屏申请次数均为 0，没有脚本异常或未捕获的 Promise 拒绝。

这些是模拟移动尺寸和权限条件的浏览器测试，不代替实体 Android、iPhone Safari 的传感器、触觉、系统自动旋转或录制兼容性测试。

解压后，将此文件夹内的内容覆盖到现有 GitHub Pages 发布目录，保持 `index.html` 位于原位置。无需新建仓库，也不需要修改原网页地址。

资源查询参数和兼容性窗口版本号以 `nofs1` 结尾。旧包仍单独保留，便于比较。
