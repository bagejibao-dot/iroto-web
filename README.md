# Iroto Web — nofs10

版本：`2.14.1-beat-haptic-stronger-logo-v3-browser-nofs10`

直接基于 nofs9，保留 iPhone 媒体播放音频会话处理；没有换用旧全屏或加速度分支。

## 本次调整

### 控件防选字

对顶部/底部控制栏、播放/停止、回正、BPM、录制状态等非编辑控件，补齐标准及 WebKit 的 user-select、touch-callout 规则。事件拦截只针对控件的 selectstart / contextmenu / dragstart，不拦截正常点击、照片选择、语言选择或通用 touchstart。

保存名称输入框继续允许全选、光标定位、复制粘贴和中间编辑。全局 Escape/Backspace 返回处理排除编辑元素和已打开的弹窗，避免退格删字触发返回首页。

### 旋转后字体放大

在 html 上固定 `-webkit-text-size-adjust: 100%` / `text-size-adjust: 100%`，限制 Safari 自动文字膨胀。没有改字体尺寸、布局间距或横竖屏断点，也没有添加 `user-scalable=no` / `maximum-scale`。这是自动文字调整修正，不是禁止用户缩放。

### 录制体积检查与码率策略

nofs9 在指定 MIME 时固定请求视频 8 Mbps、音频 192 kbps；MIME 为空的回退路径则不传码率。录像继续实时捕获独立画布，不会把原始照片文件塞进视频。

现在两个平台使用同一策略：按录制画布像素数配置视频目标码率，16:9 的 1920×1080 或竖向对应画幅为 6 Mbps，4:3 为 4.5 Mbps，方图为 3.4 Mbps；最低 2.5 Mbps。音频仍请求 192 kbps。无 MIME 的默认路径也传入码率。

照片原比例、接近1080p的输出尺寸和 `captureStream(60)` 请求均不改。并不承诺实际帧率恒定60或图像细节与原码率完全相同。未更换原有格式优先级，没有强制所有平台改用另一种编码。

保存时优先采用录制器/数据块报告的真实 MIME 和扩展名。控制台 `Iroto recording details` 记录请求/报告码率、实际 MIME、宽高、时长、字节数和平均总码率，便于同条件比较；没有上传这些信息。录制完成或失败会释放本次视频捕获轨道，不关闭用于后续演奏的共享音频轨道。构造、启动和异步录制错误会清理状态并显示三语错误提示。

**码率是给浏览器编码器的目标提示，不是强制文件大小。** 不同编码器、画面、时长和实际帧数都会影响结果。目前没有用户两部手机生成的视频样本，不能确定 Android 比 iPhone 大的唯一原因，也不能保证修改后两端大小完全相同。

## 保持不变

非全屏、屏幕旋转轴同步/重新校准、灵敏度、准星平滑、取色及声音合成、Audio Session playback、强弱拍震动、录制时红白白白280ms节拍提示、计时框毛玻璃/位置/数字对齐、照片图库入口、logo及桌面图标不变。

## 更新

解压后，将项目文件夹内的内容覆盖原 GitHub Pages 发布目录，保持 index.html 的位置；无需更改网址。兼容性窗口版本后缀为 `nofs10`，HTML资源查询参数同步更新。原 nofs9 包未覆盖。

## 验证与限制

见 CHECKS.md。测试包括代码对比、本地 Chromium 的旋转往返、控件与命名编辑、失败处理和实际录制下载。没有实体 iPhone Safari / Android 手机测试，不能以模拟用户代理代替 iOS 原生选字菜单或手机编码器实测。
