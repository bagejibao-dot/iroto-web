# Iroto Web — nofs13

版本：`2.14.1-beat-haptic-stronger-logo-v3-browser-nofs13`

直接基于当前 nofs12，针对 iPhone 自动放大风险和帮助中的播放／停止示意图做小范围修正。没有重做主界面、切换其他历史分支或重新加入加速度控制。

## 本次修改

### 自动放大风险与弹窗边界

- 语言选择框原有文字仍为 11.5–12px；改成 16px，保持原来的 92/96px 宽、38px 高、圆角及位置。文件名编辑区原有 16px 保留。目的在于避免小字号表单控件成为 iOS 聚焦放大的触发入口。
- 主页和演奏控制区加入 `touch-action: manipulation`，避免快速连续点击按钮被解释为双击放大。没有加入全局 `user-scalable=no`、最大缩放限制或整页反向缩放。
- 帮助、保存和删除确认窗口读取可见视口时，增加有效值检查，并将旧方向的尺寸及偏移限制在当前布局视口内。只计算弹窗区域，不修改照片尺寸、准星坐标或录制画幅。
- 没有强行清除浏览器已有的页面缩放设置。若旧标签当前已经被放大，应先恢复普通比例后再检查新版；这不是对所有放大原因的统一诊断。

### 帮助示意图

播放／停止改为「▶ / ■」，保持44px圆框，两侧符号缩小，斜杠居中留空。图形组30×20px，实际演奏页的播放／停止按钮不改。三语共用同一示意图，说明文字沿用nofs12。

## 更新

解压后，将目录内文件整体覆盖至原来的发布目录，尤其要同步上传 `index.html`、`app.js`、`ui.css`。帮助窗口底部应显示以 `nofs13` 结尾的版本号。不需要改网址或新建仓库。

旧版本包未覆盖。本次只交付文件，没有操作已部署网站。

## 验证限制

本地 Chromium 检查见 CHECKS.md。没有实体 iPhone Safari 或 WebKit 测试环境，无法直接复现 iOS 原生的聚焦放大、历史缩放状态和真实键盘动画；不能保证用户反馈的全部放大原因已经排除。不要把 Chromium 模拟 iPhone 用户代理当成 iPhone 实机。
